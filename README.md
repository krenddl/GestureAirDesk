# GestureFlow AirDesk

Приложение для Windows x64 на .NET 8 и Avalonia. Оно распознаёт позы одной руки через веб-камеру и позволяет управлять курсором Windows.

## Быстрый запуск

Откройте `Запустить.cmd` в корне проекта. Для запуска из исходников нужны .NET SDK 8 или новее и Microsoft Visual C++ Redistributable x64.

```powershell
dotnet restore GestureFlow.AirDesk.sln
dotnet build GestureFlow.AirDesk.sln -c Release
dotnet run --project src/GestureFlow.Desktop
```

1. Откройте «Камера», нажмите «Найти камеры», выберите устройство и включите «Распознавать руку» перед стартом.
2. В «Управлении» включите мышь. Для клика удерживайте курсор на цели или выберите щипок. Для прокрутки включите соответствующий переключатель и двигайте сжатой кистью вверх или вниз.
3. В «Жестах» можно выбрать ладонь, кулак, щипок, V-жест, большой палец вверх или три пальца. Кнопка «Назначить действие» подставляет позу в правило.

### Правила и тренировка

В «Действиях» можно сохранить несколько правил в одном профиле. Выберите позу и действие, нажмите «Добавить правило», затем включите нужные правила и общий переключатель. Кнопка «Изменить» загружает назначение в редактор. «Проверить» запускает выбранное действие без камеры. В режиме тренировки распознавание показывает позу, удержание и ожидаемое действие без выполнения команды.

Для отдельного тестового или демонстрационного запуска можно задать приложению переменную `GESTUREFLOW_DATA_DIRECTORY` с путём к отдельной папке. Этот экземпляр использует собственные настройки, профили, историю и правила. Обычный запуск использует прежнюю папку данных.

### Горячие клавиши

Пока GestureFlow запущен, сочетания рассчитаны на работу и в свёрнутом окне. Если Windows отклонила регистрацию, код ошибки виден в «Настройках».

| Клавиши | Действие |
| --- | --- |
| Ctrl+Alt+Shift+1 | Камера с распознаванием |
| Ctrl+Alt+Shift+2 | Мышь |
| Ctrl+Alt+Shift+3 | Выбранное правило жеста |
| Ctrl+Alt+Shift+0 | Остановить всё |

В области уведомлений Windows значок GestureFlow открывает меню камеры, мыши, правила и общей остановки. «Выход» завершает приложение.
 
### Черновик Telegram

В «Действиях» выберите «Telegram · открыть черновик», укажите публичный @username и текст, сохраните черновик. Назначьте V-жест и включите правило. GestureFlow открывает чат в Telegram Desktop и подставляет текст. Отправку выполняет пользователь в Telegram. После смены позы курсор возобновляет движение, если управление мышью было включено. Для проверки без камеры можно нажать «Проверить действие без камеры».

В «Истории» кнопка «Выгрузить CSV» сохраняет таблицу завершённых сеансов для Excel.

## Данные и архитектура

- Core обрабатывает состояния жестов, мыши, профилей и историю сеансов.
- Vision получает кадры и выполняет две ONNX-модели через OpenCV DNN.
- Desktop содержит интерфейс Avalonia, сохранение данных и настройки правил.
- Windows реализует управление курсором, прокрутку и команды Windows.
- Настройки, профили и история используют локальные файлы. При наличии `database.connection` приложение подключает PostgreSQL. Черновик Telegram хранится отдельно в локальных данных приложения.
- Каталог `models` копируется при сборке и публикации. Кадры камеры не записываются.

## Проверка перед сдачей

```powershell
dotnet run --project tests/GestureFlow.Core.Checks
dotnet run --project tests/GestureFlow.Vision.Checks -- models
```

1. Проверить горячие клавиши поверх Telegram при обычном запуске и в свёрнутом окне.
2. На живой камере проверить задержку, щипок, прокрутку кулаком, потерю и возврат руки.
3. Пройти демонстрацию V-жест → черновик Telegram → ручной клик жестом.
4. Сохранить профиль, завершить сеанс, перезапустить приложение и сверить профиль и историю в режиме PostgreSQL.

## Модель и ограничения

OpenCV Zoo MediaPipe 2023feb, FP32, Apache-2.0:
https://github.com/opencv/opencv_zoo/tree/main/models/palm_detection_mediapipe
https://github.com/opencv/opencv_zoo/tree/main/models/handpose_estimation_mediapipe

Предобработка: RGB float32 [0,1], NHWC; ладонь 192×192, точки 224×224.
Детектор возвращает 2016 оценок и 2016×18 значений; модель руки — 63 координаты,
уверенность, сторону руки и мировые координаты. Сейчас используются только
координаты изображения и уверенность. Пороги: ладонь 0,65; рука 0,8.

Выбирается только самая уверенная ладонь; при нескольких руках выбор может
переключаться. Есть временное сглаживание; идентификации руки между кадрами и калибровки пока нет.
Поворот кисти компенсируется перед второй сетью, координаты возвращаются обратным
аффинным преобразованием. Обрезанные кисти, перекрытия и плохой свет могут давать
пропуски и ошибки. Это исследовательский этап, не готовый контроллер рабочего стола.

Кадры камеры не записываются и не отправляются в сеть. Метрики не сохраняются.
Настройки: %LOCALAPPDATA%\GestureFlow.AirDesk\settings.json, запись через временный файл.
Повреждение файла и ошибки записи показываются в настройках.

Все нативные ресурсы принадлежат одному рабочему потоку. В очереди интерфейса
максимум один кадр. Остановка кооперативная: драйвер может задержать Open/Read,
а модель — вычисление. При зависающих драйверах понадобится отдельный процесс захвата.

## Проверки

```powershell
dotnet run --project tests/GestureFlow.Vision.Checks -- models
```

Запускать из корня проекта. Проверяются:
- отказ при отсутствующей модели;
- реальное исполнение обеих сетей и ожидаемые размеры выходов;
- отсутствие обнаружения на чёрном кадре;
- 21 конечная координата в границах официального демонстрационного снимка,
  исходного и повёрнутого на 90°.

Снимок — фотографическая часть демонстрации OpenCV Zoo; он уже содержит upstream
разметку, поэтому служит проверкой подключения и геометрии, а не оценкой точности.
Лицензии источника находятся в models. Результаты tests/fixtures/check-result-*.jpg
создаются только тестом, не камерой.

Проверено на этом ноутбуке: сборка без предупреждений/ошибок; сохранение настроек
после перезапуска; поиск камеры 0; старт/стоп и повторный старт; навигация; закрытие
при захвате; камера с включёнными ONNX-сетями. Положительное обнаружение реальной
кисти на этой камере пока не подтверждено. На тестовом снимке уверенность 0,962,
при повороте 90° — 0,896. Эти числа не являются показателем общей точности.
Отключение USB и занятое устройство ещё не проверены.

## Следующие шаги

1. Проверить живую кисть: левая/правая, поворот, расстояние, освещение, потеря руки.
2. Добавить тесты на независимых неразмеченных снимках и измерить задержку.
3. Добавить устойчивый выбор руки при нескольких кистях.
4. Настроить пороги жестов и добавить демонстрацию Palm Menu.
5. После проверки распознавания подключать Windows-действия с защитой от случайного запуска.

Пакеты: Avalonia 11.3.12; OpenCvSharp4 и runtime.win 4.13.0.20260627.





## Версия 0.4: сглаживание и жесты

Core содержит независимые от камеры геометрический классификатор и состояние сеанса. Экспоненциальное сглаживание по времени (90 мс) применяется перед классификацией и рисованием.

Подтверждение: минимум 180 мс и три наблюдения одной позы. Изменение кандидата снимает подтверждение. Потеря руки, низкая уверенность, неверные точки, разрыв кадров более 250 мс, обратное время и резкий перенос сбрасывают фильтр/удержание. При частоте ниже четырёх наблюдений в секунду жест может не подтверждаться.

Правила основаны на углах суставов и расстояниях относительно ширины ладони. Щипок: кончики большого и указательного пальцев сближаются менее чем на 0,28 ширины ладони; отпускание от 0,38. Дополнительное ограничение положения относительно запястья уменьшает путаницу с кулаком. Открытая ладонь: четыре выпрямленных пальца и отведённый прямой большой палец. Кулак: четыре согнутых пальца. Промежуточные позы — «Не определён».

Раздел «Жесты» показывает состояние, кандидата и удержание. На камере есть краткий статус. Аналитика считает подтверждения, а не каждый кадр. Остановка снимает жест; новый старт сбрасывает счётчик. Ошибка распознавания сохраняет видеопоток.

Проверка без камеры и моделей: `dotnet run --project tests/GestureFlow.Core.Checks`.
Проверяются три позы, масштаб/поворот, вырожденная кисть, удержание, отсутствие повторов при удержании, потеря/возврат, разрыв времени, неверное число точек, низкая уверенность, NaN, сглаживание, резкий перенос и гистерезис щипка. Vision дополнительно классифицирует открытую ладонь на реальных выходах ONNX для двух ориентаций снимка.

Кулак и щипок проверены на синтетических данных, но не подтверждены живой рукой. Открытая ладонь проверена на одном демонстрационном снимке. Точность в разных условиях не измерялась. Личные проверки перечислены в MANUAL_CHECKS.md. Системные действия не выполняются.


## Версия 0.5: Palm Menu

Внутренняя демонстрационная панель с переходами в Камеру, Жесты, Аналитику и Настройки.
Открывается вручную в AirDesk/Palm Menu. Escape и кнопка закрывают панель.
Управление жестами включается отдельно и не сохраняется между запусками:
подтверждённая ладонь открывает панель, кулак закрывает, потеря руки и остановка
захвата закрывают её. Промежуточная поза не меняет открытое состояние.
При удержании ладони после ручного закрытия панель может открыться снова на следующем кадре.
Панель находится внутри окна; отдельного прозрачного окна и выбора щипком пока нет.
Кнопки панели выполняют только навигацию. Системные действия отсутствуют.
Проверены автоматические переходы состояний и интерфейс: ручное открытие, переход в Аналитику с закрытием панели и Escape. Исправлен запуск на небольшом экране: окно открывается развёрнутым.


## Версия 0.6: автоматизация навигации

Раздел «Автоматизация» содержит одно правило: подтверждённый жест → выбранный раздел приложения.
По умолчанию выключено. Правило и журнал последних десяти срабатываний существуют только в памяти.
После включения или смены настройки сначала отпустите выбранный жест. Повтор требует отпускания,
минимальная пауза — 2 секунды. Потеря руки считается отпусканием; при нестабильном распознавании
возможны новые срабатывания после паузы. Это не защита для системных команд.
Кнопка проверки выполняет выбранный переход без камеры и помечает запись как тест.
Проверено через интерфейс: переход в Аналитику кнопкой, возврат и запись в журнале.
Тесты Core проверяют отключение, отпускание, одиночное срабатывание и паузу.
Действия Windows не подключены. Совместная работа с живыми жестами требует личной проверки.

## Версия 0.7: история сеансов

Аналитика показывает последние 30 сеансов с кадрами: время начала, профиль,
номер камеры, длительность, показанные кадры, среднюю частоту отображения,
число подтверждений жестов и итог захвата. Сеансы без кадров не сохраняются.
Длительность включает открытие камеры и загрузку моделей, поэтому средняя частота
не равна аппаратной частоте камеры. При аварийном завершении текущий сеанс может потеряться.
Файл: %LOCALAPPDATA%\GestureFlow.AirDesk\history.json. Запись через временный файл.
При повреждении исходный файл не перезаписывается; ошибка видна в аналитике.
При ошибке записи запись остаётся в памяти. Видео и точки руки не сохраняются.
Тесты Core проверяют запись/чтение, замену, сортировку, лимит, FPS и повреждение файла.

Проверено через интерфейс 0.7: камера 0, старт/стоп, запись 958 кадров за 33,1 секунды,
появление итога в аналитике. Проверено содержимое history.json на диске.
Восстановление после перезапуска проверено тестом хранилища; отдельный перезапуск UI не выполнялся.

## Версия 0.8: ручные медиакоманды Windows

Автоматизация → Медиа Windows: тише, громче, звук вкл/выкл, воспроизведение/пауза.
Используется SendInput (Windows x64), пара нажатие/отпускание, проверка количества
принятых событий. Ошибка показывается в интерфейсе; успешная отправка не означает
подтверждённую реакцию проигрывателя. Поддержка медиа зависит от приложения и Windows.
Жесты по-прежнему выполняют только навигацию и не отправляют медиакоманды.
Самостоятельно проверены кнопки Тише и Громче: Windows приняла обе пары событий.
Фактический уровень звука и реакция проигрывателя ещё требуют проверки.
Документация: https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput

## Версия 0.9: медиакоманды правилом жеста

В списке действий доступны Медиа: тише/громче/звук/пауза. Для реального жеста
включите правило, отдельную опцию медиакоманд и распознавание камеры.
Окно должно быть активным. Уход из окна снимает опцию медиакоманд, Escape
снимает её и выключает правило. Автовключения после возврата нет.
Кнопка проверки может реально отправить выбранную медиакоманду, но только
при включённой отдельной опции в активном окне. Обычные ручные медиакнопки
работают самостоятельно. Неопределённая поза не считается отпусканием;
отсутствие руки или другой подтверждённый жест разрешают новое срабатывание.
Проверено в UI: выбор медиадействия, блокировка без опции, включение и сброс
опции по Escape. Сборка и Core-проверки пройдены. Живая связка жест-медиа
и сброс при переходе в другое окно ещё требуют отдельной проверки.

## Версия 0.10: сохранение выбора правила

«Сохранить выбранное правило» записывает жест и действие в settings.json вместе
с существующими настройками. При запуске выбор восстанавливается, но правило,
медиакоманды и камера остаются выключенными. Старые файлы настроек совместимы:
по умолчанию щипок → аналитика. Некорректные индексы отклоняются загрузчиком.
Ошибки сохранения показываются в разделе Автоматизация.
Проверено самостоятельно через UI: выбор кулака, сохранение, закрытие приложения,
перезапуск, восстановление кулак → аналитика с обеими выключенными опциями.
Сборка без предупреждений и ошибок; тесты совместимости и сериализации пройдены.

## Версия 0.11: указатель AirDesk

В AirDesk/Palm Menu добавлена панель из четырёх областей. Камера передаёт
сглаженные точки; кончик указательного пальца проецируется из кадра в панель,
с учётом зеркального режима. Подтверждённый щипок выбирает область и выключает
указатель. Для нового выбора его нужно включить снова и отпустить щипок.
Потеря руки скрывает курсор, остановка камеры, Escape, уход из окна или переход
в другой раздел выключают указатель. Системный курсор не изменяется.
Включение указателя не выключает отдельное правило автоматизации: для чистой
проверки оставьте правило выключенным, иначе один щипок может вызвать оба действия.

Проверено автоматически: проекция, зеркало, границы, неверные данные и четыре области.
Проверено через UI: расположение панели и переход в Аналитику её кнопкой.
Живая связка палец → указатель → щипок ещё не проверена.

## Версия 0.12: рабочая область указателя

В AirDesk/Palm Menu доступны горизонтальный и вертикальный отступы 0–40%
с каждой стороны. Оставшаяся центральная область камеры проецируется на всю
панель; координаты за ней ограничиваются краями. По умолчанию весь кадр.
Кнопка «Весь кадр» сбрасывает выбор, «Сохранить область» записывает его в settings.json.
Изменение области выключает указатель. При включении указателя автоматически
выключаются правило автоматизации, медиажесты и открытие Palm Menu ладонью;
после выхода эти функции не включаются обратно автоматически.
Проверены геометрия, зеркало и сериализация области тестами Core. Через UI
проверены изменение ползунка, пересчёт подписи, сброс и сохранение.
Проверка удобства наведения живой рукой и восстановление изменённой области
после перезапуска UI ещё требуются. Запуск и сборка без ошибок и предупреждений.

## Версия 0.13: экспериментальная мышь Windows

Камера → включить распознавание → Старт. AirDesk/Palm Menu → Управлять мышью Windows.
Кончик указательного пальца двигает настоящий курсор основного экрана; подтверждённый
щипок отправляет одиночный левый клик. Сначала отпустите щипок. Пауза между кликами
две секунды; удержание не повторяет клик. Используются зеркало и сохранённая область.
